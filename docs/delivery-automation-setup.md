# Delivery setup and current release state

The workspace owner can save an automatic daily email limit under Setup → Brand & Email Identity. Presets are 5, 10, and 20; Custom accepts 1–500. New workspaces default to 5. The backend enforces the same 1–500 range for workspace and mailbox limits. The detailed Manual/Automatic mode, working days, timezone, send window, follow-ups, pause, and emergency stop remain in Delivery.

Production keeps `AUTOMATIC_GMAIL_DELIVERY_MODE=manual_only`; the server now defaults to manual-only if the switch is absent or misspelled. Setup shows the Manual and Automatic modes, but Automatic cannot be selected until the production switch is enabled and Gmail is connected. Saving a limit cannot send email while this switch is off; manual Gmail delivery requires an explicit action. Changing the switch requires a separate end-to-end pilot with a real mailbox and a controlled recipient.

A workspace currently has one Gmail connection. The mailbox and workspace counts are consequently the same, and the send window plus minimum delay may keep actual throughput below a high custom ceiling. Supporting multiple mailboxes and a larger organization requires connection routing, separate mailbox counters, reply ownership, and sender reputation controls. The current custom ceiling does not imply multi-mailbox support or guaranteed throughput.

The server accepts automatic queue requests only for addresses with `email_status=verified` on the matching, active CRM company; the scheduler rechecks this status before Gmail send. Public listings and pattern candidates marked unverified stay out of unattended sending. When the owner activates automatic mode, the app queues locally approved messages whose selected person matches a verified CRM contact at the exact company domain. Later approvals can join the queue automatically, and the owner can rescan approved messages in Delivery. Missing contacts, invalid branded snapshots, or previous outreach stay out of the queue. The app does not create or approve campaign messages autonomously.

Activity visible in the automatic panel: Gmail-confirmed sends today, queue size, next eligible send, blocked-by-limit count, automatic sends, failures, replies, interested replies, and meeting requests. A meeting request is a classified reply, not a booked meeting. The runner stores Gmail message/thread IDs and reply outcomes. Open rate, bounce analytics, multi-mailbox routing, and full autonomous campaign creation are not implemented; they must not be presented as verified measurements.
