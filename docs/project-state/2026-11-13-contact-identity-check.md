# Per-person identity check

Owner request: replace the per-person LinkedIn control with one Check identity button. Additional research belongs to that person; successful identity confirmation makes both separately approved paid channels available. An incomplete email search is not an identity conflict.

Root cause: the old per-person resume reused the company-wide continuation reset, retrying unrelated failed tasks and people. UI and paid authority also required all public contact-search checks, conflating person confirmation with contact discovery coverage.

Implementation: an explicit `check-identity` command (also used by retained per-person resume clients) persists one selected ID in the existing job. The registered scheduler skips roster acquisition/reconciliation and performs two public indexed LinkedIn queries, at most one exact-profile fallback, and an official-page check when needed. A two-minute safety cap and six new task slots bound the pass, including scheduler continuation. Ordinary company discovery retains its previous phase and all sibling data. No paid contact reveal is part of this action.

A server-owned, versioned identity outcome binds name, ID, title, organization, company/domain, profile and identity source. Fresh source-supported identity plus complete profile-search receipts is required; source failures, namesakes, conflicting current employers and stale/mutated evidence stay blocked. Official-page fallback requires matching name and role on a current attributed page. The shared paid-readiness function supplies both card state and paid-request authority. Existing full public-research completion remains valid; incomplete email/phone coverage is preserved as incomplete. Native paid approvals, provider settings, budgets, exact membership/company/revision guards and paid receipts remain intact.

Keep: existing queue/leases/checkpoints, scheduler registration, public matching, native confirmation, receipts and CRM IDs. Improve now: selected-person scope and one authoritative readiness policy prevent unexpected retries and contradictory buttons. No new table, automatic spending or manual verification override. Rollback is a code rollback; additional identity receipts are additive, retained evidence and contact data are unchanged.

Acceptance: controlled native HTTP -> registered scheduler -> fresh desktop/mobile browser, selected-only public searches with unfinished sibling unchanged, both ready controls and both Cancel paths, zero paid attempts, incomplete contact-search preservation, failed/conflicting/expired evidence rejection and guarded paid scope. These controlled fixtures do not establish the result in a customer's inaccessible authenticated session. Exact-SHA deployment proof is recorded separately in the release artifact.
