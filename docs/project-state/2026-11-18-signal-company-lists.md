# Reference and signal company lists

User-approved outcome: start from one reference, recommend 3–5, select up to 15 per search without shrinking existing reference libraries. Build named lists targeting 10/50/100/200 or a custom 1–200 count. Select one or several signals, any/all matching and optional importance. Keep references independent of search geography and monitoring configuration. Save lists/companies in CRM, download CSV/Excel, and enter Buyers only through an explicit company action.

Ownership: saved workspace reference analyses and signals supply the criteria; company_lists in D1 owns each frozen criteria snapshot, research queue, execution receipts and ranked results. Existing CRM records retain their data. List deletion does not delete CRM companies. CRM saves use bounded 20-company requests and can safely retry after partial failure. No contact research or outreach runs during list building.

Research: only selected signals contribute to relevance. Read-source quotes, official-domain identity, target-market evidence and matching reference quotes are required. Event signals need a dated source within a year. Confidence is capped for limited evidence. Fit is not buying intent. Existing public search/page-reading adapters and the workspace's reasoning provider perform actual work; receipts distinguish successful/failed operations. Search, read and reasoning each consume a saved operation allowance; this is not a billing-credit balance or price. Continuation retains completed work and grants only the user-visible next allowance.

Lifecycle: authenticated HTTP queues and registers a bounded wake; the real minute scheduler continues under a shared invocation budget. A lease prevents concurrent work and authorization is rechecked before dispatch and persistence. Cancellation invalidates late completions. One active list per workspace and at most 50 retained lists bound concurrency/storage. Quota triggers account for both criteria and source state. Existing profile/reference storage and discovery are not migrated. Rollback can remove the UI and scheduler registration while preserving D1 records.

Acceptance: pure scoring/selection/export tests; real HTTP/SQL and registered cron tests for 10 and 200 results, budget/provider pauses, cancellation, session revocation, isolation, CRM preservation and deletion; browser checks for criteria selection, progress, save/reopen and downloads on desktop/mobile. Providers are controlled fixtures; actual customer research yield remains distinct from test/release proof. Exact production SHA requires all CI, matching manifest, backend health and mandatory smoke checks.

Observed acceptance: seven backend/browser tests pass with real HTTP/SQLite persistence and registered scheduler execution, including storage-full recovery, 200-result continuation, all CRM save batches, browser downloads, fresh-browser reopening and explicit buyer selection. The pure model also checks accumulation of independently verified signals and formula-safe CSV/XLSX output. Production research yield and a private customer's configured-provider health are not inferred from these controlled fixtures.

Release integration: the shared scoring module triggers Backend CI and backend deployment evidence. The customer browser journey is mandatory in Customer CI; three additional production smoke checks cover the model, UI and backend capability marker. Returning-browser loader URLs are revised so reference guidance and the buyer adapter reach existing sessions.
