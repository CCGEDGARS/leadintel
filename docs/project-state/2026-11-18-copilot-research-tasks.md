# Reviewed research tasks in Ask LeadIntel

Owner-approved outcome: requests such as “use references from Flow 1 to find 50 relevant companies in Denmark” become saved, reviewable tasks. Ask material questions together, identify missing references and context mismatches, and show Flow, geography, ranking, quantity, buyer scope, contact evidence requirements, provider limits and output before Run. Free text never directly authorizes provider dispatch, paid contact research or CRM changes.

Ownership: a task freezes the reviewed Flow context without changing the active Flow or its settings. Existing company-list and buyer research jobs own their respective evidence and execution receipts. The task coordinates these jobs, publishes progress and pauses on required gaps. No sending or template mutation is authorized. Existing provider/channel spending policies are authoritative; no implicit activation, provider switching or budget increase. Phone attribution and reachability remain distinct.

Durability: SQL-backed plans and checkpoints, revision checks, session/workspace membership, parent-task cancellation and bounded scheduler admission protect dispatch and late writes. Completed child work is reused on explicit continuation. Missing credits, invalid credentials, absent references and essential evidence failures display red action-required states; temporary retries and optional gaps use warning states. Targets are goals, never fabricated result counts.

Acceptance: actual chat/HTTP clarification → reviewed Run → registered scheduler → ranked companies → optional buyer research → blocked/complete outcomes → export/CRM save → fresh-browser reopen. Include missing Flow/references, country conflicts, paid denial, provider limits/errors, partial preservation, cancellation/revocation, concurrency and cross-workspace isolation. Controlled provider fixtures, exact production proof and private customer research outcomes remain separate.

Implemented boundary: durable `copilot_research_tasks` coordinates existing company-list and buyer jobs through the registered minute scheduler and HTTP Run wake. Natural-language task requests and recognized follow-up answers create/update a plan; dedicated controls authorize execution. Scope is 1–200 companies, 1–15 analyzed references for lookalikes, any/all selected signals, optional 0–4 decision-makers across up to 10 top companies, and in-app/CSV/Word (.doc)/browser PDF output. Company web/analysis operations have an explicit allowance; extending it requires a separately labeled control. Buyer work retains the existing finite source/committee plan and run windows. No promised money estimate or free provider subscription is implied.

Paid contacts use the supported Treg automatic path only, with the reviewed channel, a buyer-count cap, saved workspace limits and existing qualification/public-check gates. Phone requests do not authorize email lookup. Provider/channel policy changes invalidate ongoing task authority even when changed within the same timestamp second. Newly discovered companies may need company qualification before paid lookup; this is a visible blocker, never a fabricated qualification. Source-attributed phones and exact-person provider verification are separate labels; reachability is not promised.

Cancellation, permission revocation, storage failures, source/required-check gaps and exhausted allowances retain results. Task children cannot write after parent pause/deletion. Deleting a conversation cancels its children and leaves completed company evidence as an independently manageable list. Existing CRM company records are reused without replacement; the explicit Run summary discloses the company handoff for buyer research. Save companies in CRM does not claim to overwrite or export an entire workspace. Legacy buyer input keys and manual research behavior remain unchanged.

Controlled acceptance covers authenticated HTTP planning, clarification, revised-plan validation, registered scheduler completion, source-backed named-phone outcome, public-only execution, phone-only paid intent with no actual paid provider dispatch, same-second paid policy changes, red credit blockers, allowance extension, partial preservation, storage failure, pause/revocation, workspace isolation, browser close/reopen, CRM saves, CSV/Word downloads and PDF print preview. Artifacts are recorded by the mandatory browser CI job. These controlled sources prove the implementation journey; they do not claim new contacts from a private customer's production data. Release status requires the exact-SHA proof separately.

Rollback: application code can be reverted while retaining the additive task table and its evidence. Stop active reviewed tasks before rollback; do not drop the table or delete CRM/source history. A later restoration can resume only through reviewed controls and current permission checks.
