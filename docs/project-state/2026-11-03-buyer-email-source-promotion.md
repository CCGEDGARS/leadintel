# Confirmed email source promotion

The live refresh check reproduced a confirmed official email losing its read proof: a later unread result repeated the same person and address at another URL, replacing the primary evidence with context that had no source-read receipt. The earlier confirmed source check still existed, but it no longer matched the displayed source binding. This reduced the usable-contact count while research was running.

For the same full identity and address, discovery and pool merging now retain the complete previously accepted source binding until a replacement actually passes the existing recipient/source policy. Confirmation is never transferred to the unread replacement URL. A verified new source may replace it; a failed original binding, expired proof, different identity or different address cannot inherit confirmation. Existing qualification and employment holds remain authoritative.

Matching prioritizes read sources and known bound URLs within its existing twenty-row view. Research prefers the current accepted source, or the matching confirmed source check when evidence was already overwritten, so a retained read task can repair the record without another source fetch. Save/reload, client checkpoint restoration, CRM serialization and actual scheduler regressions verify this behavior. No source, research-depth, authority, paid-policy or sending gate is relaxed.
