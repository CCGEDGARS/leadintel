# Review the next saved companies — 20 October 2026

The Companies page now offers a visible Review next X companies button above the ranked shortlist. X follows the selected amount, the remaining pending count and the existing maximum of 30 company checks per run. Its message explains how many saved companies await review and that the next batch updates evidence, scores and ranking. Each click runs the existing scoped recheck pipeline for those saved identities; it does not open broad market discovery or fabricate scores to fill the shortlist. Existing purchasing-fit, evidence, budget and manual/automatic qualification rules remain in force.

The root usability gap was that incomplete companies were available only inside the collapsed additional-results review, with an advanced recheck action that did not identify a next batch. A persisted least-recent-attempt queue now prefers unattempted companies, then the oldest incomplete attempts. Explicit identity ordering is preserved through execution before applying the thirty-company cap, so cancellation or timeout cannot spend first on old retries ahead of untouched members. Completed companies leave the queue, while insufficient evidence remains pending and can be retried after other pending companies. Explicit target identities are filtered before the existing thirty-company cap, so later saved entries remain reachable. The requested amount still controls only the main visible ranked checked cards; additional results remain available on click. Previously selected Buyers, people, checked companies and their evidence are preserved.

Review metadata belongs to the current workspace, seller, offer and strategy. Changed context invalidates old ordering; late work cannot write to another workspace. Overlapping clicks are blocked. Cancel restores the priority of unfinished members, completed work remains saved, and an interrupted reload resumes the unfinished reservation. Task Centre and visible failed-check retries retain the batch identities. Independent review found that the generic failed-check fallback could escape into broad discovery; a real-runner HTTP 402 regression reproduced that behavior before routing batch-owned failures back through the scoped batch wrapper. Review Remove/Clear actions are blocked during research to prevent deletion/reappearance races; explicitly clearing all company results also removes queue history. No page load or rendering starts research. Clicking Review is the user's explicit request to run that batch through the existing provider pipeline. This change does not activate contact reveals, automation or outreach.

Regression coverage uses the real runner, qualification engine and DOM controls with simulated external provider responses: pending count and selected amount; consecutive fair batches and persisted reload; actual different scores and reranking; preserved Buyers; no broad search; overlap; rejected targeting; cancel; interrupted reload; thirty-company bound and later identities; offer reset; workspace and strategy races; deletion guard; actual button dispatch; queue completion/clear; and seller exclusion. Runtime cache markers, a mandatory production smoke check and the production-watch fixture cover the new controls. Full verification and independent review are recorded after execution. Provider simulation proves control flow and score handling; no paid live batch or real-world matching yield is claimed.
