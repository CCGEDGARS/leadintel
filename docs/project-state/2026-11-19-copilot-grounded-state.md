# Ask LeadIntel: saved facts and evidence

Owner request: connect assistant answers to actual app state and researched outside information. Preserve the advisory boundary and reviewed research controls.

## Observed causes and ownership

- Strategy cards, Profile trigger descriptions and signal weights were supplied without exact, separate counts. The saved workspace owns active/off/deleted choices; prose cannot activate a signal.
- The integration context interpreted `active=0` as disconnected. This field chooses the main generation engine; verified secondary providers remain connected.
- Caught read failures could become empty arrays or zero counts. Missing telemetry is now explicitly unavailable.
- Research opportunity counts used a bounded sample. Source records, opportunities, report snapshots, verification and execution receipts now have separate fields.
- Company details favored the top ten even when a question named another saved candidate. Named candidates and CRM companies now receive priority within the bounded context.
- Earlier conversation statements and client observations lacked a saved revision/time. Every loaded context now has a server snapshot and a separate, untrusted browser save-state observation.

No authenticated private customer session was available for this investigation. The screenshot established a discrepancy, not a complete production incident trace.

## Result

Direct state questions use calculated saved facts without AI generation or external searches, including in thorough mode. Diagnostic and recommendation questions retain model reasoning with fresh scoped context, exact counts, gaps and bounded-detail notices. Other questions retain public research and existing source-reading paths.

Connections, configured research preferences and executed research remain distinct. Microsoft Mail is included. A failed read is unknown rather than zero/disconnected. Deleted signals stay deleted; inactive profiles stay inactive. Selected Flow data comes from the saved workspace pointer and a workspace-scoped Flow lookup.

Answers expose a dated **Basis for this answer** panel, navigation to relevant steps, and unsaved/version-mismatch notices. Evidence persists in chat history, durable research answers, copy and PDF output. Old answers remain snapshots; a new turn reloads current state.

External citation numbers must refer to the actual returned source list; extra allowed product links cannot manufacture citation numbers. Unmatched URLs/references are marked unverified. Search summaries, page extracts and model summaries remain distinguishable. Research synthesis and follow-up planning do not stream unvalidated citations. This is provenance checking, not a claim that an LLM or cited page guarantees truth.

## Verification

- Authenticated HTTP + real SQLite: one active signal with weight nine; off/deleted distinction; injected client state rejected; saved changes override earlier answers; history preserves original revisions; secondary Gemini remains connected beside main Claude; foreign workspace denied; database failure never becomes zero.
- Real saved Flow create/open routes: switching Flows changes the selected name and active signal count; saved reports, sources, failure category and verification status stay separate.
- Bounded summaries: totals cover all records and omitted details are explicit; a named low-ranked company is included without confusing numeric name prefixes.
- Controlled external research: only actual source IDs are accepted; unsafe/unsupported links are rejected; premature researched answers are not streamed.
- Chromium desktop/mobile: chat, source-basis panel, Strategy navigation, print evidence, fresh-browser history and refreshed answers. No page errors or real provider spend. Required in Customer CI.
- Existing Copilot, Firecrawl usage, research/task lifecycle, security, memory, streaming, customer UI and release tests retained.

## Operational limits and rollback

No schema migration, paid lookup, settings edit, CRM mutation or outreach send is introduced. Summaries remain bounded; the assistant does not have unrestricted access to every record, mailbox or outside system. Model-written advice can still require review. Runtime errors and customer acceptance remain separate from exact-SHA release verification. Rollback is the source revision; additive message metadata is backward compatible.
