# Step 1 Setup recovery contract — 2 November 2026

## Outcome and authority

An authenticated customer can enter and activate a company website, choose countries, attach readable PDF/image evidence, save, reopen and continue to Profile with the same source identity, quotes and revisions. Uploading, extraction, readable partial coverage, AI analysis, profile preparation and human approval remain distinct observations. No outreach, paid contact lookup or automation activation is authorized by Setup.

The last successfully activated company owns the canonical website and downstream work. A proposed website is a draft until its own extraction succeeds. File objects and processing leases own their outputs; an old worker must not overwrite or delete a newer worker's source. Acknowledged workspace persistence owns cloud-save status. The material component owns uploads and their status, while Profile consumes only readable current material revisions. Country selection remains country-only; legacy regions migrate without erasing countries.

## Confirmed causes and changes

- Website blur/input previously committed a replacement and cleared downstream work before extraction. `setupWebsiteDraft` now preserves the proposal separately; verified activation commits it. Failed, cancelled or late reads preserve canonical evidence and work. Keep current company discards only the proposal. Exact URL/path matching preserves other website pages and citation positions.
- Activation and persistence had one undifferentiated retry. A failed cloud save now exposes Retry workspace save using the already extracted source, with exact source/account ownership. Cancelled operations cannot release a newer operation's controls or clear its error.
- Material controls used the shared confirmation API incorrectly, polled readiness too late and accepted stale/malformed responses. The controls now use the real filename/string-and-options dialog, immediate readiness, revision validation and list/mutation ownership. Ambiguous uploads stop the batch and reconcile before another submission.
- OCR now fills unreadable physical pages while retaining nonblank native text. Aborted processing cannot publish fallback evidence. Processing outputs use lease-specific private keys and conditional publish; expired cleanup first claims its own lifecycle. Full metadata quota still records Needs attention without repeating paid work. Bounded metered orphan cleanup preserves all current references and delays failed deletions so they cannot starve later cleanup.
- A successful settings PUT triggered an old-policy redraw and re-enabled Save before refresh completed. Failed/superseded refreshes also cleared drafts and falsely reported success. Transient Gmail state was incorrectly part of draft/write ownership, allowing two PUTs to finish in the wrong order. Setup now has stable draft/write ownership separate from sending authority, locks controls through the current read acknowledgement, validates the returned mode/limits, and retains an acknowledged choice with read-retry recovery when reload is unavailable. Account switches still invalidate old results and finalizers.
