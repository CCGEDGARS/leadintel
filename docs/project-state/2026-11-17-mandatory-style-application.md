# Mandatory email style application and latency

## Outcome and authority

An explicit style selection applies the current approved master for that channel and style. Core builtins use the canonical deterministic renderer; published owner replacements use the current protected registry record. Personal templates and edited drafts remain separate. No canonical wording or factual permissions change.

The reported screenshot contains a saved working copy with a warning that it cannot be verified against Professional. Its historical creation path is not established by the screenshot. Reopening preserves saved text, but an unverified working copy must not display an applied mandatory-style checkmark. Explicit selection restores the approved wording with persistent Undo and repairs an obsolete first-original snapshot without deleting its history.

## Confirmed causes and changes

- Every style click fetched the entire script catalogue, personal library and preferences. An authenticated selected-core query now reads only that registry slot and returns its current body/contract without revision history. Each click still checks current owner edits and deletions; cached builtin text cannot bypass a newer master.
- Managed email templates waited for public research before displaying the master's wording. They now fill known values and display the exact master immediately after its authority check. Missing values stay visible. Editing and saving the incomplete working draft stay available while bounded research continues for missing facts; only the same untouched, unsaved draft may receive its completion. Another style cancels prior work, and late results cannot overwrite another style, recipient, manual edit or saved copy. The original action's Undo boundary survives factual completion.
- Factual preparation caches were confined to a single style even when another style used exactly the same source fields. Reuse now requires the same sender/recipient identity, matching per-field source, current source master version and successful parsing/rendering under the selected master's limits. Changed facts or identities reject reuse. An empty cache still uses the existing bounded preparation path.
- Selecting a managed style no longer opens Writing Assistant as an extra side effect.

## Acceptance

Tests cover current-master lookup, owner replacement/deletion, membership, all mandatory style rendering, the saved generic-copy screenshot case, cross-style field reuse/invalidation, delayed research, rapid switching, manual/save races, persistent Undo and CRM reopening. The authenticated Messages browser journey records style-application duration and provider calls while preserving its cold-provider failure and recipient-switch checks. Those failure scenarios explicitly clear prepared caches so they exercise the provider boundary instead of successful reuse.

Controlled provider fixtures establish application behavior and timings under those conditions. They do not establish the exact customer's current saved script history or external provider latency. No outreach is sent by style selection, research or these tests. Deployment requires a separate exact-SHA production proof.
