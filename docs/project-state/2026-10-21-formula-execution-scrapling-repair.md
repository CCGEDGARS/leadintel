# Complete company search plans and protected extraction

The dossier previously inserted only eight formulas and 500 characters into a general research objective. A completed leadership/contact search therefore did not prove that the internal formulas ran. The dossier now executes every supported formula separately for each independent researcher, alongside leadership and company-contact searches. Each query records its exact objective, attempts, grounded completion, results and timestamps. Completion requires the whole matching plan and source-supported extraction from two different providers. OpenAI and Anthropic adapters require successful actual search execution, rather than a requested search or a failed tool result.

Plans accept up to 30 formulas, each at most 2,000 characters. Oversized plans fail explicitly. Provider attempts remain bounded at 90 seconds, two concurrent searches, 20 selected sources and eight pages per extraction batch. Formula and extraction checkpoints survive retries; completed searches and extraction batches are reused. A changed formula changes the context signature. Legacy completion flags cannot satisfy the new coverage gate. Refresh resumes a matching partial plan while work remains; an exhausted plan with no usable evidence can be restarted explicitly. Workspace normalization and CRM preserve query and source-read receipts, including the latest incomplete attempt when prior sourced findings remain visible.

Scrapling's production failure was authentication: the identified Render service recorded 30 extraction requests on 21 October, all HTTP 401. The Worker and Render credential were synchronized using a reviewed one-time encrypted handoff; no plaintext credential entered the repository or logs. The temporary repair workflow was then removed. Authenticated runtime checks returned HTTP 200 with actual Scrapling content from example.com and Stegra's official website (171 and 6,701 characters respectively). These service checks do not constitute a completed customer contact-research run.

The extraction chain also starved its final fallback: dossier reads allowed 18 seconds while direct reading and Firecrawl could consume 15 seconds before Scrapling. The sequential allocator now reserves fallback time within the existing 18/25-second page ceilings. The Python runtime receives the remaining budget, shares it across guarded redirects and makes one SDK attempt. The browser allows five seconds for the bounded server response to arrive. Parent cancellation still stops the chain. Safe authentication, HTTP, timeout and blocked-content diagnostics survive workspace and CRM reload; reused sources are labelled explicitly.

Published company channels, named contacts and confirmed company mailboxes remain separate. Generated addresses remain guesses. Public research does not authorize paid contact reveals or outreach. A passing release check proves code freshness; complete formula coverage and usable contact outcomes must be assessed from the customer's actual research receipts.
