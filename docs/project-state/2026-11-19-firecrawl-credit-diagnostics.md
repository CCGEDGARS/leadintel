# Firecrawl credit investigation and Ask LeadIntel

The owner reported a customer using their free Firecrawl allowance in about ten minutes, then identified Alberts, Microsoft sign-in, and November 17. Those details do not establish a workspace ID, an exact time interval, or billed requests. This execution environment has no authenticated customer/Cloudflare account access. No customer credentials or provider billing history have been read, and no customer-specific root cause is claimed.

Confirmed implementation defects: the HTTP Firecrawl proxy used the workspace rate gate, but direct backend search/extraction in buyer and company research, monitoring, source health and approved workflows bypassed it. These paths did not share a complete usage record. Ask LeadIntel's cost keywords could themselves initiate paid external research; its prior usage context covered AI token activity and dated provider balances rather than Firecrawl requests. A ten-minute allowance loss can also be legitimate because searches may request extraction of multiple results. That explanation is a possibility, not an incident finding.

`firecrawl-request.js` now owns metered backend Firecrawl transport. Every search/scrape adapter uses the existing workspace gate; the interactive proxy keeps its existing bounded wait, and background callers receive an explicit local 429 when no slot is available. No retry loop, hidden spend approval, new provider, relaxed evidence rule or pricing guarantee is added. Customer-only keys, provider failure handling, public-first reads, independent search fallback, membership checks and cancellation remain governed by their callers. The gate remains workspace-scoped: another app or workspace sharing the same Firecrawl team is outside its full view. Existing fail-open behavior on gate-storage failure is preserved; it is not a hard credit-spend cap.

Each metered attempt records a workspace-scoped receipt: endpoint, bounded feature label, timestamp, response category, provider-reported credits when available, separate standard-operation estimate, and a workspace-salted request hash. URLs, query text, personal data, raw provider responses and credentials are excluded. A network attempt does not prove the provider received or billed it. No old charges are reconstructed. Local holds are unbilled; other missing credit amounts remain unknown. The new receipt namespace retains at most 10,000 rows or 30 days with per-minute pruning; existing audit namespaces are untouched. Diagnostics explicitly disclose retention, missing history and truncation.

Firecrawl usage questions now take a deterministic read-only support path before model/research dispatch. They return recorded requests by feature, actual reported credits versus estimates, repeated identical requests, failures versus rate limits, the date of the last saved balance, and official billing-log/recovery guidance. A repeat does not prove a bug; an absent record does not prove zero spend. ISO dates and bounded minute/hour/day windows are supported. Follow-up credit questions retain the provider context, while another named provider is kept separate. Even thorough mode or a dashboard URL must not start a research job. The reply and safe report persist in ordinary chat history; no operational settings or CRM records change. This support works without AI credits and makes no provider calls.

Acceptance covers concurrent HTTP/background admission, actual/unknown/zero credit amounts, failure/no-retry behavior, privacy and cross-workspace isolation, historical windows, unavailable storage, authentication, real HTTP/SQLite chat save/reopen, and desktop/mobile Chromium. Tests use controlled credentials/providers and cannot settle Alberts's invoice. Reconciliation requires the affected account's Firecrawl Usage/Logs for the same time window and API key, including other clients using that key.

Rollback: revert this change; no schema migration or operational-data conversion is required. The added bounded diagnostic receipts can remain. Exact-SHA customer/backend CI, production manifest, backend version marker and release proof are separate publication gates.
