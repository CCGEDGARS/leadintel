# Manual Confirm data

Approved by Edgars on 21 October 2026. The buyer action is now **Confirm data**. It reuses saved/public email evidence, then offers a manual Treg professional-profile lookup and an optional phone lookup for the exact selected buyer. It remains usable when an email already exists. Automatic paid-search activation is not consent to these extra profile/phone calls; the manual dialog always asks, with Cancel and an email/profile-only alternative.

The dialog shows maximum Treg operation costs: email finder $0.05 + independent mailbox verifier $0.025 + profile $0.05 = $0.125; optional phone $0.10, combined maximum $0.225. Each phase has its own enforced request ceiling. Actual settled micro-USD and call IDs remain in phase receipts; monthly phase keys reuse completed responses. AI/public/company research is separate. This is a ceiling, not a guaranteed bill or a promise of coverage.

Profile fields are provider-reported, not a new confirmation of employment or authority. Conflicting returned names, company domains or LinkedIn URLs are rejected. Retrieved phone numbers are **provider listings, reachability and ownership unconfirmed**. They never become a verified email or unlock a recipient. The data action updates only the chosen person and CRM research snapshot; the existing email acceptance and sending gates remain unchanged. The button becomes **Data updated** when fields were returned without phase errors; partial/empty results are shown honestly. Manual confirmation never activates or sends outreach.

API: existing authenticated `/api/additional-contact-services/email`, with `data_lookup: true` and optional `phone_approved: true`, provider `treg`, individual `approved: true`, `automatic: false`. Automatic callers cannot request the added phases. Normal automated enrichment remains work-email-only. No database migration or new credential is required.

Treg endpoints verified against the public catalog on 21 October 2026: `treg.people.enrich` and `treg.people.phone.find` (POST with name/domain and optional LinkedIn/email). Treg's shared Apollo endpoint refuses Apollo mobile reveal; the routed phone endpoint avoids promising that unavailable feature. Sources: https://treg.to/catalog/endpoints/treg.people.enrich ; https://treg.to/catalog/endpoints/treg.people.phone.find ; https://treg.to/tools/apollo .

Verification covers manual consent/cancel, phone exclusion, existing-email reuse, missing-email/profile survival, conflicts, phase failures, workspace normalization, real SQLite CRM persistence and no repeat paid-phase fetches. Controlled provider responses prove implementation, not live contact availability or a customer-paid lookup. Production claims require exact-SHA release proof. No real outreach is sent by these checks.

Final review controls: snapshot writes resolve the selected buyer identity atomically inside SQLite, guarding id/name/title/profile; per-phase guards also recheck profile identity. New profile/phone idempotency incorporates exact identity and profile. Existing email-phase keys remain compatible with saved pre-upgrade receipts, so interrupted email lookups do not repay completed phases. Excluding phone preserves historical evidence without writing that number over a later CRM correction. A profile-only retry preserves earlier phone evidence. A new verified email counts as updated data even when enrichment finds no further fields. Manual Treg selection does not inherit a legacy automatic Apollo provider setting.
