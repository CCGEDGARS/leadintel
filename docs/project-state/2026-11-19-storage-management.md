# Storage monitoring, file cleanup and optional report copies

The owner requested a storage monitoring bar, deletion of unnecessary files and an option to avoid automatically retaining unnecessary content. Pricing and free-capacity proposals remain separate: this change does not activate Stripe, change prices or change allowances.

Settings → Storage retains the server-authoritative data/file meters and adds percentages, amber 80% and red 95% meter states. Manage files & saving lists company materials and books, largest first, with accounted sizes, download links and explicit owner-only deletion. Files still being processed cannot be deleted from this panel. Deletion reuses the existing source endpoints, revision guards, durable cleanup and R2 quota accounting. The confirmation states the effects; saved derived skills remain independent of book deletion. This inventory is not an exhaustive list of every storage object or CRM record.

A workspace-owned preference controls optional automatic research report snapshots. Existing behavior is preserved by default. Turning it off preserves existing reports, current source evidence, diagnostics, monitoring findings, saved workflows and versions. Explicit Save current report remains available. Identical report copies and empty automatic snapshots are skipped. Opening the research panel no longer persists a migrated copy simply by viewing it. Missing/failed preference checks skip only the optional copy and explain recovery. Preference updates require owner authentication, an allowed origin and optimistic revision matching, and remain available at storage capacity.

Existing identical-company-file upload deduplication and abandoned-book-upload recovery remain in place. No AI classification deletes content as “garbage”, and no broad age-based cleanup of useful source evidence is introduced.

Migration 0079 adds two small preference columns without changing stored content or quota limits. Old workers ignore these columns; UI/backend rollout is compatible. Rollback leaves data and preference intact, though older clients do not honor manual-only report copies. No cleanup is performed on real customer files by deployment.

Validation includes SQLite quota/authentication/CAS tests; customer cancellation, stale-workspace and save/reload tests; actual Workers migration/status checks; and an authenticated Chromium → real HTTP routes → SQLite/R2-fixture journey, including mobile layout and metered deletion. Live customer-file deletion is intentionally not an acceptance step.

Research completion now awaits the bounded optional-copy decision before releasing its run lease. A valid normalization of the same market does not invalidate that decision: the copy is written into the current market object after evidence and account checks. Acceptance waits for the actual saved report, then verifies source counts, partial-run errors, verification coverage, Companies handoff and a fresh browser reopen. The three research modes and interrupted-provider journey passed together (36 checks), with the additional delayed-workspace and normalization regressions passing separately.

Buyer research can exhaust the CRM record allowance while the independent file meter has capacity. A Nordisk Staal diagnostic recorded a failed official-source checkpoint, eight saved checks and seven Firecrawl credits. The Storage screen subsequently showed 99.41 MB of 100 MB used for records. Neither figure identifies the distribution of that workspace's saved records.

When a buyer checkpoint exceeds remaining space, the worker retries its guarded database write with a lossless encoded copy. Resume on a storage-blocked job compacts up to twelve large terminal buyer checkpoints in the same workspace and resumes the saved phase. Only smaller, round-trip-verified results are committed. Roster and recovery indexes remain accessible to SQL. Receipt dates, job revision, workspace quota, file storage and paid approvals are preserved by compaction. If a previously measured checkpoint still cannot fit, Resume reports the minimum record-space shortfall before opening another execution window. The prior generic storage error may lack a byte measurement. The production database must be served by a checkpoint-aware reader after compact writes begin.

Platform admins can open Settings → Storage → Edit storage plans and workspace limits. Standard CRM and file allowances flow into the same account columns used by the database and object-storage guards. Workspace overrides persist until the admin chooses Use standard limits. Migration 0089 retains existing custom limits, usage counters and payment entitlements. Reducing an allowance below usage pauses growth and preserves existing content. Restoring the previous limits is sufficient to roll back a quota change.

The optional EUR monthly amount applies to new Checkout sessions. A blank amount selects the configured Stripe Price. An edit writes no Stripe objects. The first checkout at a different price needs Prices Write on the configured restricted key and creates a recurring Price for the validated storage product. Previously issued price IDs must remain in the database for renewals. Keep the pricing-aware webhook handler when rolling back frontend changes. Billing activation remains a separate merchant configuration.

The Storage card opens a workspace-scoped inventory. Category measurements are generated from the installed SQLite quota triggers by scripts/generate-storage-inventory.py. The detail endpoint pages through items without transferring their contents. Individual deletion uses the owning feature or a scoped older-backup/version action. Protected current backups and shared workflow chunks are retained. After deletion the manager rereads both meters.

## 28 November · Manage storage could not open the inventory

The earlier inventory tests used SQLite to calculate category sizes. The Workers D1 regression exercised the status endpoint alone. Opening the authenticated files endpoint on Workers D1 reproduced the customer's 503 banner. A query joining 16 category totals exceeded the runtime's five-term compound SELECT limit. Grouping at most five terms per query returns the inventory and preserves the byte calculation for every category.

The dialog previously discarded both reads when either the inventory or the preference failed. It now keeps the successful section and shows which section needs a retry. An unavailable preference displays an indeterminate, disabled checkbox. The Workers test covers inventory, category details and preferences. The browser journey covers individual section failures, retry, owner controls and reopening on mobile. Testing uses fixture records. This repair requires no data migration or billing change.
