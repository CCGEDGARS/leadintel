## Confirmed remaining code cause

On base `a6dc7202`, the explicit review branch of `runCompanyDiscovery` hydrates complete official raw reads and clears a historical `needsRecheck` only after a fully eligible current assessment. Normal discovery has a different saved-queue implementation. It neither hydrates those complete reads nor clears the old flag before asking `companyEvidencePlan` whether web acquisition is needed. Its five-company query wave also differs from explicit review's progressive execution.

Three actual-run regressions fail before their respective corrections:

1. Fresh readable candidate evidence plus `needsRecheck:true`: normal discovery makes **3 controlled web calls** instead of zero.
2. Same candidate, with the required attributable employee count only in the complete executed raw read: normal discovery makes **49 controlled web calls** instead of zero.

3. The saved-only task retry omitted `savedEvidenceOnly` from its registered callback and made **3 controlled web calls**. Forwarding the owning no-web constraint keeps retry at zero calls. The dispatcher boundary remains unchanged.

These numbers are fixture dispatches, not measured customer costs. They prove another entry-path divergence; they do not establish that this is the sole cause of every historical failure or the remaining private customer's shortfall.

## Implementation contract and architecture decision

Keep the shared qualification/evidence policies, existing budget dispatcher, workspace scope/cancellation guards, CRM authority and durable Buyer scheduler. Improve now: remove the duplicate saved-company executor. Both normal discovery and explicit review call one `reviewSavedCompany` routine inside the owning run. It merges executed official raw reads, reassesses saved facts, clears recheck only after current eligibility, acquires only the missing facts when permitted, and checkpoints completed results before the next company. This prevents the demonstrated split from being patched in one caller alone.

No schema migration, source timestamp rewriting, evidence threshold changes, new provider permission or deletion. Source URLs, complete read bodies, original read times, saved company identities and existing selected Buyers remain intact. Only the changed UI loader is advanced; release URL prefixes remain intact. Rollback is a source revert retaining all saved state.
