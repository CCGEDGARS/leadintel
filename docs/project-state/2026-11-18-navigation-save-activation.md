# Navigation must not create workspace edits

User outcome: clicking any sidebar step, expanding sections, viewing saved pages or changing unsaved list-setup controls must leave the saved indicator unchanged and must not upload the workspace. Genuine edits, recovery, pending acknowledgements and conflict resolution still need their existing save protection.

Reproduction through the real HTTP/SQLite browser fixture showed Profile navigation calling Strategy seeding. It changed ICPs, signals, opportunities and approval state, then Companies marked its retained research stale. Step navigation also flushed the whole stale in-memory app object through saveState, and the hidden save control remained enabled while clean. These are mutation ownership issues, not just a status caption problem.

Changes: page navigation writes only the saved page position, preserving newer independently owned fields. Rendering saved Strategy does not generate or activate new data, invalidate approval or persist legacy repairs. Explicit profile approval, edits, reference updates and research retain their mutation/validation paths. Unchanged legacy profile edits preserve approval. The fallback storage bridge ignores navigation-only writes using the existing semantic content contract. Deferred input/change observations act only when stored content changed during the event; filters and local form drafts therefore cannot queue a save. Repeated comparisons reuse a bounded per-section result for unchanged raw snapshots. Clean save controls disable; real edits, failed saves, browser-only data, conflict and pending write recovery remain actionable.

Acceptance: actual sidebar clicks across all seven stages, repeated navigation, expanding/collapsing, list setup, zero cloud PUTs and unchanged Strategy/messages; real website proposal saved through the toolbar and retained after reload. Controlled provider fixtures are used. Unit coverage protects no-op profile saves, account guards, independent saved fields, fallback bridge classification, comparison caching, actual edits, concurrent writes, reversions, recovery and conflict handling. Exact production proof is required separately.
