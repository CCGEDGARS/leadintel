# Message language controls — 10 October 2026

English remains the source. Saved languages, default language and selected translation target are separate explicit preferences in `outreach.messageStudio.languageSettings`, within the saved flow payload. Flow reopen preserves its preferences instead of overlaying another flow's language. Duplication carries the configuration and retains the required language-review checkpoint. Flow cards display the preferred outreach language instead of the English generation/source language.

Add language stores a supported target without translating the draft. Set as default selects the target but preserves the displayed message. A language tab opens an existing version or asks for explicit Translate. Translate stays visible when language settings are closed, translates the English subject/body, uses the existing editorial review and fact/layout guards, preserves independent edits/history, and saves the result. English selection opens the original without an AI request. Remove switches an active removed version to the actual original, defaults back to English when necessary, and archives the translation/history for Undo through CRM serialization. English and legacy originals cannot be removed. Sync, busy, edit/preview, approval and context-race guards remain enforced.

Root causes: the previous target existed only in a DOM dataset, tabs selected a different active version, and no preference or removal controls existed. A separate existing recapture bug in translated/restorePrevious overwrote the replacement with the currently displayed old version. Displaying an already-captured replacement now avoids a second capture.

Manual Add to flow requires a reviewed saved version in the configured default language. Existing server automatic template generation is English-only; a non-English preference invalidates approval and blocks automatic template generation instead of silently sending English. This change does not implement unattended multilingual AI generation or authorize any sends.

Regression coverage includes five added languages, explicit defaults and source preservation, closed-panel Translate targets, recoverable removal/history, actual CRM roundtrip, saved-flow composition/duplication/isolation, automatic language gates, and existing translation context-race rejection. Exact release proof and authenticated production evidence are recorded separately after publication.

## Authenticated rendering correction

The first signed-in production check caught a new temporal-dead-zone error: translation controls referenced the local `editorState` before its declaration in `renderMessageWorkspace`. Initialize that state before the language panel call and guard editor busy/saving as well as edit/preview. A regression executes the actual composer renderer with the real language UI for idle, editing, preview, busy and saving states; isolated module tests did not cover this caller ordering. Production acceptance must include the signed-in assembled composer, not only static assets and individual module tests.
