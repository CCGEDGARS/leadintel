4. Campaign source hash omitted canonical main.market/Strategy approval and public_linkedin_url recipient alias. The reviewed hash now binds the shared canonical source stamp and original public profile alias. Direct campaign/provider submission receives source_authority only after exact persisted reviewed hash match. Approval/history/draft text is retained on invalidation.
5. Campaign lease claim was an unguarded direct update; the lease/revision did not survive delegated queue/provider waits. Claim now shares request/source/control assertions. campaignDispatchAuthority pins original lease, revision, expiry, reviewed member and full current source read set through queue SQL and manual provider reservation/OAuth/submission (provider owner wiring). Its submitted-payload check compares exact subject/body/canonical HTML/original recipient/domain and rejects unreviewed followups.
6. Historical campaign sequences could add never-reviewed followups or change persisted initial HTML. campaignDeliveryAuthorized now rejects nonempty campaign followup content, and binds persisted queue step 0 subject/body/recipient/canonical HTML to the original reviewed draft. Queue owner also rejects forged external campaign prefixes and pins campaign assertions in the initial enqueue transaction.
7. An orphan expired campaign lease could silently permit replay. It now holds pending reconciliation. The explicit authenticated owner recover-delivery action and mounted UI confirmation never send: only original bound terminal failed transport reservations or already persisted delivery outcomes can release a lease; failed members return to review with original drafts and approval cleared. Missing/sending/accepted-but-unreconciled receipts remain held. Recovery pins original token/revision/account and exact SQL receipts; no blind lease clearing is exposed.
8. Operational stage hooks covered neither active saved-flow execution nor the internal eight-stage to visible-seven-stage mapping. The shared observeWorkflowStage wrapper now records actual execution plus checkpoint outcomes for both runners: profile2/strategy3/companies4/buyers5/triggers4/messages6/crm6/delivery7. Safe operation/run/revision/action correlation is retained. Profile/Strategy record reviewed validation only, never research yield. Held/shortfall work records partial; failures/stale authority record their actual terminal outcome. Receipt storage is best effort through the shared owner helper.
