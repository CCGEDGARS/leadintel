## Actual data path and evidence types

1. `app.js`, activated website, saved target markets, optional links and material records feed `company-research-ui.js`. Missing Setup textarea no longer means clear saved optional links. A tentative URL differing from the activated website is rejected.
2. `firecrawl-workspace-router.js` maps the browser's legacy-looking Firecrawl URLs to authenticated `/api/integrations/services/firecrawl/search|scrape`. The service path uses the workspace's configured Firecrawl v2 connection, with its implemented direct fallback after scrape error. The distinct public-first adapter has a separate direct → Firecrawl → configured Scrapling path; its existence does not prove Profile executed Scrapling. Receipts identify actual paths and counts.
3. Queries derive from active seller/domain/offers/markets and page categories. Main/optional sources, internal links and authoritative-page searches are extracted; public result discovery remains supporting evidence. Source URL/final URL, text, category, extraction status and evidence IDs are preserved. Foreign redirects cannot become same-company proof.
4. `company-research-engine.js` filters evidence, evaluates coverage and builds bounded drafts. Synthesis calls the selected workspace AI through `task: profile-synthesis`, using only supplied evidence, without implicit web search. A generated paragraph is not a website-read receipt. Uploaded documents and pages are explicitly untrusted data, never authority to change system instructions.
5. Research metadata retains provider/model, supplied queries, execution receipts, result counts, coverage/failures, generation/failed-attempt times and field provenance; profile normalization keeps active seller evidence distinct from historical evidence. A retrieval timestamp is not the source publication date or proof a claim remains current.
6. `profile-engine.js`, canonical intelligence/runtime and the editable intelligence Profile retain sourced claims, user statements, AI interpretations/commercial hypotheses and missing values. AI inference remains inference even when it cites a page. User review/confirmation is not independent external verification. Unknown remains unknown. Evidence cards link retained IDs/URLs and show missing targets. `company-brain.js` keeps field-specific claim associations rather than attaching every source to every claim.
7. `reference-customers.js` and reference portfolio/lifecycle modules keep customer examples separate from seller identity. Reviewed publishing, list activation/deactivation and deletion are distinct. Explicit inactive/empty portfolio state reaches Strategy localization and Companies ranking without reviving legacy drafts.
8. Canonical editor → shared brief → core ICP/Company Brain → Strategy uses current offers, markets, exclusions, customer characteristics, buyer-role/buying-outcome context and active reference model. Custom segments/manual work remain intact. Material edits invalidate approvals and preserve prior evidence/history. Strategy approval and Companies/Buyers business acceptance remain separate audits.
9. Local normalized state → account-scoped workspace bridge → versioned authenticated customer-state routes → workspace persistence is inherited from Instruction 1. Local acknowledgement is not cloud durability: sync conflicts and failed save remain actionable with local recovery. No code automatically chooses local/server legitimate edits to clear a conflict.

JSON serialization/normalization/reload and evidence rendering were exercised. No dedicated native Profile export was discovered/verified; do not label all export/print formats PASS.

## Monitoring and incident investigation

Reuse the Setup trace and backend `audit_events`; no separate monitoring platform or schema. `LeadIntelReliabilityTrace` aliases `LeadIntelSetupTrace`, with stage-2 research/synthesis/edit/approval actions and `leadintel:profile-operation`. Retain at most 100 copied records, safe operation/context IDs, timestamps, phase/outcome and trace version. Clear on account/workspace/cache invalidation; no credentials, raw source text, queries, URLs or customer draft bodies enter this diagnostic buffer.

Profile search/extraction/synthesis sends a bounded `X-LeadIntel-Operation-Id`, backend validates/replaces it, response/retained execution receipt and existing service/AI audit metadata correlate it. The ID is diagnostic, not authorization, billing proof or an idempotency key. Backend access/deadline failures remain failures. The existing first-party proxy preserves this header.

For a reported issue, compare latest failed attempt against the last useful evidence/Profile rather than deleting the latter; inspect execution receipts for actual provider/status/result counts, then safe operation ID in authorized backend audit access. Compare field source IDs and extraction status for missing provenance; compare approval signature/context for stale review; compare workspace state version/sync conflict for persistence failure. A configured connection proves neither execution nor source truth. Logging remains best effort and the local trace is not durable; missing events cannot prove no external call occurred. Stale rejection and persistence/approval failure are visible diagnostics, not a new alerting service.
