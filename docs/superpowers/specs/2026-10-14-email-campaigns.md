# Selected-recipient email campaigns

Approved user goal: Prepare a campaign below Prepare for an event in Step 1, use a selected recipient group and a shared template, tailor/review each message in Step 6, and deliver in Step 7. Existing CRM contacts, CSV import and new discovery feed the group. Campaigns never activate sending during setup.

Use dedicated D1 campaign/member tables, excluded from workspace JSON. Campaign creation and edits require authenticated workspace writers; sending/queueing requires owner approval. Scope every read/write to workspace. Resolve recipient facts from live CRM, deduplicate emails and default selection to one contact per company. Preserve imported originals at the user side; import CSV values into CRM without claiming verification. Existing suppression/email-confirmation policy applies at delivery.

Templates: approved core styles use the canonical deterministic renderer; saved custom templates use supported slots; an explicitly written campaign template supports firstName, buyerCompany, role, sender, sellerCompany and trigger. Same-wording mode retains a shared body with identity substitutions; personalised mode additionally uses verified CRM trigger facts. Unfilled/unknown fields block that recipient. No AI invention or changes to masters.

Each campaign member owns a separate draft, fingerprint, approval and delivery result. Preparation, import, approval and queue operations process bounded batches of at most 20. Campaigns support up to 500 selected recipients. Existing drafts are never overwritten by Prepare missing messages. Message edits clear approval. Preview/review and explicit group approval precede queueing. Recheck CRM identity, suppression and seller context immediately before sending. Use existing Gmail/Microsoft manual delivery and Gmail automatic delivery paths; preserve idempotency and mailbox limits. Queue only this campaign's approved recipients. Queue failures remain individually visible/retryable. No real emails sent during development.

UI: Step 1 expandable card with saved campaigns, name/objective, recipient sources, searchable paginated CRM picker, CSV input, template and save; Step 6 campaign message table with preparation progress and per-recipient subject/body editor and approval; Step 7 campaign-only queue/manual send controls, statuses and links to existing scheduling settings. Resume after reload from server. Clear all client campaign state on workspace change and reject late responses.

Verification: real SQLite route tests for scope, persistence, duplicates, suppression, stale approvals, import and exact selected queue handoff; DOM tests for card placement, selection and context-race rejection; canonical template regression suite, full customer/backend CI, build, independent review and exact-SHA release proof. Authenticated real-provider behavior is separately reported.
