# Workspace storage and billing

User authority: Edgars asked to proceed with the storage update; prior instruction delegated workload assumptions (one user, two flows, ten emails/day), included storage in Settings, red full alerts and paid upgrades. Resume the agreed functionality without another approval round. No customer charge, outbound financial transfer, live subscription or provider billing change is authorized in this engineering acceptance run.

## Design

One workspace has one shared entitlement. Included capacity: 100,000,000 bytes of structured customer content and 1,000,000,000 bytes of private files. Storage Plus: 500,000,000 structured bytes and 10,000,000,000 file bytes. Decimal MB/GB. Price assumption EUR9/month; actual Checkout amount comes only from a configured active EUR monthly Stripe Price, never a browser price or a hardcoded payment link. Show both meters and current plan, yellow at80%, red at100% or confirmed payment failure, yellow on connection failure. Warn and preserve existing data; block only growth, permit reads and reductions. Membership authorizes status; owner alone authorizes checkout/portal.

Count logical persisted customer content, not SQLite pages/indexes or operational/authentication secrets. D1 transaction triggers keep exact counters and enforce limits in the same write, including background jobs and multi-statement rollback. Future workspace-content tables require migration coverage tests. Brand binary chunks count as files. Private R2 object writes reserve exact bytes before upload, serialize replacements with operation tokens, keep failed reservations counted until reconciliation, and release only after confirmed deletion. Existing R2 keys are backfilled with object heads before declaring file usage exact. Size-bearing legacy metadata is never presented as zero verified usage.

Stripe hosted subscription Checkout, flexible billing, merchant ccgroup.lv; no Connect or vendor payout. Persist first-class Stripe Customer -> workspace mapping. Verify webhook signature over raw body and livemode, enforce bounded request, deduplicate committed event IDs, fetch canonical subscription/latest invoice to withstand replay/out-of-order events. Grant Plus only for a paid configured-price invoice period; renewal extends paid-until, failed invoice produces red billing status, expiration/cancellation returns to included without deleting data. Ignore browser success URLs as entitlement authority. Resolve checkout via Stripe object graph and owned Customer mapping. Customer portal handles payment method/cancellation. Config missing means disabled checkout and honest setup status, never simulated payment success. Restricted keys and webhook secret live only in Worker secrets. Validate intended merchant and configured Price/product before creating Checkout. No automatic_tax until registration/configuration is confirmed. Use latest documented stable API/SDK after verification.

Cloudflare bills the operator's existing account separately, automatically against its configured payment method. Stripe settlements fund the operator business account; no per-customer forwarding or automatic card/bank setup is attempted. R2 capacity is elastic but D1 has a shared physical limit; platform monitoring and future sharding remain necessary and are not represented as unlimited storage.

## Cost assumption

10 sends/day x30 x(8 KB message +4 KB follow-up/reply/audit) is3.6 MB/month. Two flows x20 researched companies/month each x30 KB is1.2 MB/month; total4.8 MB/month, roughly57.6 MB/year, before additional research history and uploads. This is an assumption, not measured account usage and not a guaranteed period; if flows discover20 companies/day instead, structured usage can exceed40 MB/month.100 MB base is an initial quota, upgrade before growth exceeds it. File allowance covers ordinary documents/images, not media archival. R2 and D1 operations, Worker compute, AI, enrichment, fees and tax are separate costs.

## Verification

Real SQLite migrations/counters, isolation, Unicode/BLOB sizing, bootstrap backfill, growth blocked/reduction allowed, expired paid plans, atomic rollback and overlapping saves. R2 upload/replacement/delete failure and legacy reconciliation. Signed Stripe events with duplicates, forged/mismatched accounts/modes/customer/price, unpaid checkout, renewals, late failures and cancellations. Owner/nonowner controls, no secrets, setup-disabled checkout, async workspace-change UI guards and red/yellow alerts. Full backend/customer CI and exact-SHA production proof, then authenticated Settings with actual workspace usage. Live money movement is excluded.
