# Book-derived workspace skills

Approved through the 27 October conversation and “lets do it”.

Content Library gains Books and Skills tabs. Three book slots remain. Turn to skill is disabled until completed analysis supplies a summary and readable content. Confirmation names the skill, discloses exact coverage and explains automatic enablement. Skill title equals saved book title without its file extension.

Up to 30 skills per workspace including disabled, processing and failed skills. Creation is idempotent by source content hash. Each skill snapshots all readable extracted sections and the complete analysed catalogue independently of the book. A resumable scheduled job develops source-linked methods, decision rules, procedures, questions, checklists, original examples and limitations for every chunk, then publishes only when all chunks are complete. No completeness claim for unreadable pages. Source deletion cannot remove any completed or in-progress skill snapshot.

Skills have View, Download ZIP, enabled switch, retry and explicit Delete. Export contains SKILL.md, supporting method files and a source/coverage manifest; no original full book or app credentials. Skill deletion cleans its own objects and cancels generation. Generation failure preserves completed sections. User-owned provider billing applies.

Ask LeadIntel selects zero to three enabled relevant skills and useful sections. Selection is semantic through the existing customer model and validated against workspace-owned IDs. A small Skills used indicator records only model-reported use of supplied skills. Skill methods are untrusted supplementary knowledge; cannot override system safety, protected templates or authorize operations. Writing Assistant offers explicit selection of up to three ready skills with existing draft/source race protections.

Approach: build on private R2 book storage, D1 workspace membership and minute scheduler. Separate skill records and objects give durable independence. Rejected: storing a link to the book (breaks deletion), and using just the short summary (insufficient depth). No base-model retraining or globally installed ChatGPT skills.

Builder choices: use the existing JS stack without a ZIP dependency; store bounded chunk outputs in R2; fail closed on incomplete generation; atomic capacity enforcement and revision guards. Existing source scope, owner mutation rules, operational boundaries and core masters remain authoritative.
